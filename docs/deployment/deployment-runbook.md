# PULSE — Deployment Runbook

**Audience:** whoever ships PULSE to a real gym (pilot). **Scope:** a single-gym production pilot.
**Status of the app:** feature-complete for MVP + Arabic RTL + polish; gate green; not yet deployed.

> **Read this first — three facts that shape everything below.**
> 1. **HTTPS is mandatory.** Auth.js v5 uses `__Secure-` session cookies under `NODE_ENV=production`; browsers reject them over plain HTTP, so **sign-in silently fails without TLS**. Every recommended path terminates TLS for you. (This is the whole "prod-auth gap" noted in dev — it is *not* a code bug; `trustHost: true` is already set.)
> 2. **PostgreSQL 18 is NOT required.** IDs are UUID-v7 generated by Prisma in the app (no DB-level `uuidv7()`), so **any managed Postgres 14+** works. The `docker-compose.yml` PG18 is a local-dev choice only.
> 3. **Migrations run from a full-workspace release step, never from the runtime image.** The slim production image does not contain the Prisma CLI or `prisma/migrations/`.

## 1. The environment contract (platform-agnostic — always true)

The app **refuses to boot** unless these validate (`apps/web/src/env.ts`, Zod fail-fast):

| Var | Required | Value / how to get it | Notes |
|---|---|---|---|
| `DATABASE_URL` | ✅ app + migrations | `postgresql://USER:PASS@HOST:5432/DB?sslmode=require` | **`sslmode=require`** for essentially every managed PG. Use the **pooled** endpoint if the host offers one (Neon/Supabase). |
| `AUTH_SECRET` | ✅ app | `openssl rand -base64 32` | **Strong and STABLE** — rotating it signs everyone out (JWT sessions). Store in the platform secret store. |
| `NODE_ENV` | ✅ (`production`) | `production` | Enables secure cookies (needs HTTPS) + `info` logging. Most platforms set it for you. |
| `OWNER_INITIAL_PASSWORD` | ⚠️ **seed step only** | a strong password you choose | Seeds the bootstrap owner `owner@pulse.local`. **Not read by the running app.** Rotate after first login. |
| `PULSE_LOCALE` | optional | `ar` (default) / `en` | Only a fallback default; users pick their language in-app (cookie). Leave unset → Arabic. |
| `LOG_LEVEL` | optional | `info` (prod default) | `debug` for troubleshooting. |

**Not needed:** no `NEXT_PUBLIC_*`, no `AUTH_URL` (omit it — `trustHost:true` derives the host; set it *only* if redirects misbehave), no OAuth keys, no `POSTGRES_*`/`DATABASE_URL_TEST` (local/CI only).

**Toolchain (build host):** Node **≥ 20.11**, pnpm **9.15.4** (pinned via `packageManager`), and **outbound network to Google Fonts at build time** (`next/font` fetches Inter / JetBrains Mono / Noto Sans Arabic / Space Grotesk; without network the build degrades to fallback fonts). Runtime needs neither.

## 2. Recommended path — long-running Node container + managed Postgres

**Why this over serverless/Vercel:** the app is now **100 % dynamic** (the per-user locale cookie makes even `/sign-in` server-rendered), so there is no static/edge win from Vercel; and Prisma prefers **persistent connections**, which a long-lived container gives you without pooling gymnastics. A container PaaS also hands you **TLS + secrets + a release command** out of the box.

**Concrete stack (a good default):**
- **App:** a container platform — **Fly.io** (default recommendation), or Render / Railway (equivalent; pick by preference). Deploys the committed `Dockerfile`.
- **Database:** managed Postgres **in the same region** — the platform's own (Fly Postgres / Render / Railway PG) or **Neon**. **Choose an EU-Central / Frankfurt region** for Egypt/Gulf latency (or a Gulf region if the provider has one).
- **TLS + domain:** the platform's automatic HTTPS on its subdomain, or your custom domain.
- **Backups:** **enable automated daily backups + point-in-time recovery** (see §5 — this is a hard requirement, money data is sacred).

### 2.1 Deploy steps

> Steps marked **[you]** run against real infra with your credentials/domain — I did not perform them. Steps marked **[verified]** were validated locally in this repo.

1. **Provision** the managed Postgres (Frankfurt) and copy its connection string; ensure `?sslmode=require`. **[you]**
2. **Set secrets** on the app platform: `DATABASE_URL`, `AUTH_SECRET` (`openssl rand -base64 32`), `NODE_ENV=production`. **[you]**
3. **Migrate the database** — from a full-workspace context (CI job, the platform's *release command*, or your machine pointed at the prod DB), **not** the runtime image:
   ```bash
   pnpm install --frozen-lockfile
   pnpm build                      # generates the Prisma client + compiled seed
   DATABASE_URL=<prod-url> pnpm --filter @pulse/db db:deploy   # = prisma migrate deploy
   ```
   `migrate deploy` reads `DATABASE_URL` from ambient env (its loader tolerates a missing `.env`). **[verified: `db:deploy` is `prisma migrate deploy`; migrations apply cleanly on PG in CI]**
4. **Seed once** (idempotent — creates RBAC + the bootstrap owner + the `PULSE HQ` gym). Run the **compiled seed with ambient env** — do **not** use `pnpm db:seed`, which hard-requires a `.env` file and throws `ENOENT` without one:
   ```bash
   DATABASE_URL=<prod-url> OWNER_INITIAL_PASSWORD=<strong-pass> \
     node packages/db/dist/seed.js
   ```
   **[verified locally against dev Postgres]**
5. **Build + run the app image** (`Dockerfile`, committed). The platform builds it and runs `node apps/web/server.js` on `$PORT`, behind its HTTPS. **[verified: image builds on Linux + boots + serves — see §4]**
6. **Point your domain** at the app; confirm the certificate is live (HTTPS). **[you]**
7. **First-login smoke test** (see §6). **[you]**

### 2.2 Alternatives (pick instead if…)

- **You already use Vercel / want zero infra.** Works, but: set the build command to run `prisma generate` (it does, via `pnpm build`); run `prisma migrate deploy` in a **separate** step (Vercel won't migrate for you); and use a **pooled** `DATABASE_URL` (Neon pooler / Supabase / Prisma Accelerate) because serverless functions exhaust direct connections. `output:'standalone'` is ignored there (harmless).
- **You want full control / on-prem.** A single VPS with **Docker Compose** (this app image + Postgres) behind **Caddy** or **nginx + Let's Encrypt** for TLS. Most control, most ops (you own patching + backups). Still HTTPS-terminated at the proxy; keep `trustHost:true`.

## 3. Repo enablers shipped with this runbook

| File | Purpose |
|---|---|
| `Dockerfile` | Multi-stage: install → build (`BUILD_STANDALONE=1`) → minimal non-root runtime running the Next standalone server. |
| `.dockerignore` | Keeps the build context lean (excludes `node_modules`, `.next`, tests, `.env`). |
| `apps/web/next.config.ts` | `output:'standalone'` + `outputFileTracingRoot` (repo root, required for pnpm monorepo tracing) — **gated behind `BUILD_STANDALONE=1`** so local Windows `pnpm build` is unaffected (standalone file-tracing uses symlinks, which fail on Windows with `EPERM`). |

Everything else (build/migrate/seed) reuses the existing scripts the CI `database` job already exercises (`.github/workflows/ci.yml`) — that workflow is the canonical, working build→migrate→seed recipe.

## 4. What I verified locally vs. what you must verify

**Verified in this repo (local — the `Dockerfile` was built + run end-to-end):**
- Full gate green: TypeScript, ESLint, architecture fitness, **200** unit, **107** integration, production build.
- Conditional standalone config does **not** break the normal Windows `pnpm build`.
- **The `Dockerfile` builds on Linux** (Docker Desktop) — standalone file-tracing succeeds where Windows `EPERM`s — producing a **291 MB** image.
- The container **boots** (`✓ Ready in 204ms`), **serves** `GET /sign-in` → **200** with `<html lang="ar" dir="rtl">`, and **auth-gates** `GET /dashboard` → **307** redirect to sign-in.
- **Prisma works in the standalone image**: pointed at a real Postgres, `GET /api/health` (runs `prisma.$queryRaw\`SELECT 1\``) → **200 `{"status":"ok","checks":{"database":"ok"}}`** — confirming the generated client + `@prisma/adapter-pg` are correctly traced into the standalone bundle and query at runtime.
- The compiled seed runs idempotently against Postgres.

> Building this image surfaced **four issues now fixed in the `Dockerfile` / `next.config.ts`**, each of which would otherwise have failed a first container deploy: (1) `output:'standalone'` breaks Windows builds → gated behind `BUILD_STANDALONE`; (2) `prisma generate` needs `DATABASE_URL` present at build (Prisma 7 `env()`) → a build-stage placeholder `.env`; (3) **Turbo filters env vars to task subprocesses**, so the standalone flag must come from that `.env`, not a Docker `ENV`; (4) the app has no `public/` dir → that `COPY` was removed.

**You must verify against real infra (I cannot — needs your DB/domain/TLS):**
- `prisma migrate deploy` over TLS to the managed DB (should report the two migrations applied).
- The **HTTPS cookie round-trip**: sign in on the real domain and confirm the session persists (this is what fails over plain HTTP — see the smoke test §6). The Prisma-in-image path is already verified above; the remaining unknown is purely the TLS cookie.

## 5. Production requirements checklist (do not skip)

- [ ] **HTTPS** on the app domain (valid cert). Auth breaks without it.
- [ ] **Managed Postgres with automated backups + point-in-time recovery.** PULSE holds financial + membership records the constitution treats as sacred — PITR is mandatory, not optional.
- [ ] `AUTH_SECRET` generated fresh, stored in the secret store, **never** committed; rotation policy understood (rotation = forced re-login).
- [ ] `DATABASE_URL` uses `sslmode=require` (+ pooled endpoint if serverless).
- [ ] `OWNER_INITIAL_PASSWORD` strong; **owner password changed after first login**; bootstrap value rotated/removed.
- [ ] Migrations run as a **release/pre-deploy step**, gated so a failed migration blocks the release.
- [ ] Region chosen for latency (Frankfurt/eu-central for Egypt/Gulf, or a Gulf region if available).
- [ ] Log drain / error visibility wired (the app emits structured `pino` JSON logs to stdout — point the platform's log drain at them).
- [ ] Currency set to **EGP** and time zone to **Africa/Cairo** in-app at onboarding (the seed defaults are USD/UTC — see §6).
- [ ] CI branch protection enabled once a remote exists (the `ci.yml` `gate` + `database` jobs are authored but dormant).

## 6. First-login smoke test (post-deploy acceptance)

1. Visit `https://<your-domain>/sign-in` → the sign-in page renders (Arabic RTL by default).
2. Sign in as **`owner@pulse.local`** with your `OWNER_INITIAL_PASSWORD`. → **session persists** (proves HTTPS cookies + the Prisma DB path in the image).
3. You are routed into **onboarding** (the seed gym has `setupCompletedAt = null`). Set:
   - **Currency → EGP** (so all money renders «ج.م», not "USD" — closes the known currency caveat),
   - **Time zone → Africa/Cairo**, gym name, branch, owner profile.
4. Change the owner password (profile/account) away from the bootstrap value.
5. Switch language ar⇄en from the profile page or the user menu → the UI + text direction flip. (Verified working.)
6. Create a member → sell a membership → record a payment against it → confirm the dashboard KPIs and reports update.

If all six pass, the pilot is live.
